Project Analysis: Proposal Governance Platform

1) Project Overview
What the project does
- This is a proposal-governance and startup-investment platform.
- It allows founders to create and submit funding proposals, reviewers to evaluate them, investors to discover approved opportunities and invest, and admins to govern the workflow.

Problem it solves
- It replaces fragmented manual governance by providing a single workflow for proposal submission and review, role-based access, real-time notifications, trust and verification features, and AI-assisted proposal analysis.

Target users
- Founders
- Reviewers
- Investors
- Admins

Overall architecture
- Frontend SPA in React
- Backend REST API in ASP.NET Core
- EF Core + MySQL for persistence
- SignalR for real-time updates
- JWT for authentication

Frontend framework and version
- Main frontend: React 19 with Vite
- Secondary UI: React 18 with Vite

Backend framework and version
- ASP.NET Core Web API on .NET 10

Database
- MySQL via Pomelo EF Core provider

Authentication method
- JWT bearer tokens
- Passwords hashed with BCrypt
- Roles enforced in frontend and backend

APIs used
- Internal REST APIs under the main governance backend
- SignalR hub for notifications and discussion updates
- Optional Gemini API integration for AI features and patent verification

External services
- Gemini API for AI analysis and patent verification
- Mock email service for notifications and alerts
- File uploads served from static files

Folder structure
- Main app: frontend/src
- Backend: backend/ProposalGovernance.Api
- Secondary funding API: backend/StartupFunding.API

Design pattern followed
- Layered architecture
- Repository pattern
- Dependency Injection
- Service layer pattern
- MVC-style controllers

How frontend communicates with backend
- The main frontend uses a centralized fetch-based client in frontend/src/services/api.js.
- It sends JSON requests with JWT in the Authorization header, file uploads via multipart upload, and real-time updates via SignalR.

3) Application Flow
- User opens the app
- The app shows login/register screen
- On successful login, JWT is stored in localStorage and SignalR starts
- Based on the user role, the app renders a different dashboard
- Users navigate to proposals, marketplace, discussions, consultations, verification, subscriptions, trust score, and analytics
- On logout, storage is cleared and SignalR disconnects

Main screens
- Login
- Register
- DashboardOverview
- FounderDashboard
- ReviewerDashboard
- InvestorDashboard
- AdminDashboard
- ProposalMarketplace
- DiscussionRoom
- ConsultationHub
- SubscriptionPlans

4) Authentication Flow
Login process
- User enters username/password
- Frontend sends POST to /api/auth/login
- Backend validates credentials using BCrypt
- If valid, backend creates a JWT and returns it

Registration process
- User submits name, email, username, password, role, department, optional patent ID
- Backend creates the user and hashes password
- Patent ID is optionally verified

Password encryption
- Passwords are hashed with BCrypt before storage

JWT/session/cookie usage
- The app uses JWT in Authorization header
- It does not use cookies
- It stores the token in browser localStorage

Authorization
- Backend protects routes with [Authorize] and [Authorize(Roles = ...)]

Role-based access
- Admin
- Reviewer
- Founder
- Investor

Logout process
- App clears localStorage and disconnects SignalR

Token expiration
- JWT expires after 2 hours

Refresh token flow
- Not implemented

5) Feature-by-Feature Explanation
Authentication and user management
- Purpose: login, register, and manage roles
- Frontend: frontend/src/pages/Login.jsx and frontend/src/pages/Register.jsx
- Backend: backend/ProposalGovernance.Api/Controllers/AuthController.cs
- Endpoints: /api/auth/login, /api/auth/register, /api/auth/verify-patent
- Database tables: Users

Proposal lifecycle
- Purpose: founders create, edit, submit, and track proposals
- Frontend: frontend/src/pages/FounderDashboard.jsx
- Backend: backend/ProposalGovernance.Api/Controllers/ProposalsController.cs
- Endpoints: GET/POST/PUT /api/proposals, POST /api/proposals/{id}/submit
- Business logic: Draft -> Submitted -> UnderReview -> Reviewed -> Approved/Rejected

Review and governance decisions
- Purpose: reviewers score proposals and admins decide approval
- Frontend: frontend/src/pages/ReviewerDashboard.jsx and frontend/src/pages/AdminDashboard.jsx
- Backend: backend/ProposalGovernance.Api/Controllers/ReviewsController.cs
- Endpoints: POST /api/reviews, POST /api/proposals/{id}/assign-reviewer, POST /api/proposals/{id}/decide

Investor funding
- Purpose: approved proposals become investment opportunities
- Frontend: frontend/src/pages/InvestorDashboard.jsx
- Backend: backend/ProposalGovernance.Api/Controllers/InvestorController.cs

Capital allocations and drawdowns
- Purpose: manage funded capital disbursement
- Frontend: frontend/src/pages/FounderDashboard.jsx
- Backend: backend/ProposalGovernance.Api/Controllers/CapitalController.cs

Discussions and messaging
- Purpose: real-time discussion rooms between stakeholders
- Frontend: frontend/src/pages/DiscussionRoom.jsx
- Backend: backend/ProposalGovernance.Api/Controllers/DiscussionsController.cs

Consultation workflow
- Purpose: founder/reviewer/investor consultations
- Frontend: frontend/src/pages/ConsultationHub.jsx
- Backend: backend/ProposalGovernance.Api/Controllers/ConsultationController.cs

Subscription and premium plans
- Purpose: paid plan logic for founders/investors
- Frontend: frontend/src/pages/SubscriptionPlans.jsx
- Backend: backend/ProposalGovernance.Api/Controllers/SubscriptionController.cs

Trust score and verification
- Purpose: establish trustworthiness of founders and startups
- Frontend: frontend/src/pages/TrustScoreView.jsx and frontend/src/pages/VerificationDashboard.jsx
- Backend: backend/ProposalGovernance.Api/Controllers/TrustController.cs and backend/ProposalGovernance.Api/Controllers/VerificationController.cs

AI assistant and analysis

- Frontend: frontend/src/components/PremiumAIChat.jsx

Notifications

12) Performance Considerations
Strengths
- API requests are centralized
- React state updates are localized
- SignalR reduces polling
- EF Core handles persistence cleanly

Potential bottlenecks
- Large single-page app with many feature modules
- Several list views could use pagination
- No visible caching layer

13) Final Summary
This is a full-stack role-based governance platform built with React and ASP.NET Core. It supports proposal workflow, reviews, investments, consultations, notifications, trust verification, and AI-assisted analysis.
